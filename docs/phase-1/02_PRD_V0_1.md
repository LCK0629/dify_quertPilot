## 1. Vision / 产品愿景

Enable retail decision makers to ask questions in everyday language and receive **authorized, correct, reproducible, explainable** business analysis. / 让零售管理者用自然语言获取安全、正确、可复核且有明确依据的分析结果。

### Core value / 核心价值

Not a generic SQL bot. QueryPilot specializes in a limited retail domain and earns trust through a semantic catalog, deterministic execution and evidence-linked narratives. / 不追求无边界问题解答，先在有限零售场景保证可靠性。

## 2. Goals and non-goals / 目标与非目标

**Product goals / 产品目标:**

1. Answer supported retail questions without SQL knowledge. / 无须用户掌握 SQL。
2. Maintain one definition of each KPI. / 统一业务指标定义。
3. Keep LLM outside the trusted query-execution boundary. / LLM 无权直接执行任意查询。
4. Provide reproducible evidence and say 'cannot determine' when appropriate. / 结果可核实，信息不足时明确拒答或说明限制。
5. Demonstrate an engineering portfolio spanning database, Python, API, AI and UI. / 体现完整 Data/AI Engineering 能力。

**Non-goals / 暂不实现:** forecasting, causal inference, external competitor intelligence, customer PII queries, writeback/autonomous operations, multi-tenant SaaS, dozens of BI chart types, freely editable SQL, mobile app. / 不做预测、真正因果推断、外部竞品情报、个人敏感数据查询、自动写回、多租户 SaaS、自由 SQL 等。

## 3. Personas / 用户角色

- **Retail owner / 店主:** asks high-level business questions; needs reliable KPI comparisons and concise explanation; can access all demo stores (test-only role). / 查看全部虚构门店。
- **Store manager / 店长:** needs store performance and breakdown; limited to authorized store IDs, enforced server-side and at DB layer. / 仅限获授权门店。
- **Business analyst / 分析师:** inspects calculations, query plan, SQL and source metadata; cannot bypass data authorization. / 可查看分析依据，但权限不越界。
- **Data steward (operator) / 指标管理员:** preconfigures metric catalog and approved views; no end-user metric editing in MVP. / MVP 由配置管理指标，不开放编辑后台。

## 4. Supported user journeys / 核心用户流程

### Journey J1 — Quick KPI / 快速指标

1. Input: 'What was our net revenue in October 2026?' / 输入问题。
2. LLM recognizes metric `net_merchandise_revenue`, month, optional scope. / 解析指标、时间、范围。
3. Validate metric, permissions and date bounds; compile query. / 权限及日期审核。
4. Execute PostgreSQL safely and return value with period/definition. / 返回指标值、期间、定义。
5. Show method/evidence with expandable SQL. / 提供可展开 SQL 与计算说明。

### Journey J2 — Compare / 对比分析

'Compare net revenue by store in September and October 2026.' → grouped store revenue, Δ and % where denominator not zero; appropriate chart and table; store scope enforced. / 跨期间、跨门店对比并计算变化。

### Journey J3 — Revenue decline investigation / 收入下降诊断

'Why did our revenue decrease last month?' → interpreted as **contribution analysis**, not proven causality. Resolve metric and last complete calendar month in dataset timezone; compare prior complete calendar month; run approved category/store/quantity/discount/refund breakdowns; reconcile sum of category deltas to total delta; show observed contributors, alternative explanations and limits. / 诊断主要数值贡献，而非臆测消费者动机。

### Journey J4 — Clarification / 歧义澄清

'How were sales?' → ask: metric (gross vs net), time period and breakdown only if required; preserve already known constraints; no speculative execution. / 参数不足先澄清，不猜数据定义。

### Journey J5 — Refusal / 安全拒答

'List customer emails' or 'DELETE all orders' → refuse unsupported or unauthorized operations; no SQL execution; record sanitized reason category. / 对越权或写入请求拒绝执行。

## 5. MVP scope / MVP 范围

**P0 mandatory / 必须有:** NL input, approved retail KPIs, ranking, time comparison, one limited revenue decline diagnostic, automatic chart/table, trustworthy written result, query provenance, two test roles with data scope, error/ambiguity states, reproducible dataset, basic audit telemetry.  
**P1 stretch / 时间允许:** inventory low-stock questions, persistent query history, saved analysis links.  
**Out / 不包含:** dashboard builder, autonomous agents, demand prediction, customer cohort/churn, unbounded LLM SQL, arbitrary cross-database joins, enterprise RBAC admin UI.

## 6. Functional requirements and acceptance criteria / 功能需求与验收

| ID | Requirement / 需求 | Priority | Acceptance criteria / 验收条件 |
|---|---|---|---|
| FR-01 | Question submission / 问题提交 | P0 | User can submit English retail questions, receive result, clarification, or supported error; each request has an ID. / 输入问题后必有明确处理结果。 |
| FR-02 | Structured intent extraction / 结构化意图 | P0 | Returns schema-validated `metric`, `time`, `dimensions`, `filters`, `sort`, `limit`, `intent`; missing essentials trigger clarification. / 必要字段校验。 |
| FR-03 | Retail semantic catalog / 指标定义 | P0 | Every available measure has version, formula, unit, allowed dimensions, allowed filters and business description. / 每项指标受统一定义控制。 |
| FR-04 | Safe plan compilation / 安全编译 | P0 | Only preapproved query patterns/identifiers/functions compile; client cannot directly pass executable SQL; all values bound as parameters. / 禁止无约束 SQL。 |
| FR-05 | Secure query execution / 安全执行 | P0 | Least-privileged PostgreSQL role, read-only transactions, resource limits, allowed views, fixed maximum rows and authorization tests. / 严格限制权限、资源。 |
| FR-06 | KPI answer / KPI 回答 | P0 | Gross sales, net merchandise revenue, completed-order count, units, booked discount and AOV calculations match independent reference for supported periods. / 指标对照结果一致。 |
| FR-07 | Period and dimension comparison / 时间与维度比较 | P0 | Month-over-month, by store/category/product; absolute difference, safe percentage change, zero-denominator handling. / 正确处理基期为零。 |
| FR-08 | Revenue contribution diagnostic / 收入贡献诊断 | P0 | Compare consecutive full calendar months; category contributions reconcile to total Δ within defined rounding tolerance; no unsupported causal claim. / 总额与类别贡献对账。 |
| FR-09 | Visualization / 数据可视化 | P0 | KPI card for scalar, line for time, bar for ranked groups, table for detail; units and filters match data. / 图形与数据语义相符。 |
| FR-10 | Evidence and narrative / 分析依据与文字 | P0 | Display period, scope, metric definition/version, data-as-of, executed SQL/plan, result table and limitations; summaries quote only returned numeric values. / 结果可复核。 |
| FR-11 | Clarification and unsupported handling / 澄清拒答 | P0 | Unsupported metric/field, ambiguous period, or unauthorised scope generates non-execution response. / 未获授权不执行 SQL。 |
| FR-12 | Role-based access / 权限控制 | P0 | Store manager never retrieves other stores in data/results/LLM context; analyst/owner scopes configured and validated server-side. / 不跨店访问。 |
| FR-13 | Operations trace / 操作追踪 | P0 | Request ID, metric version, time, policy decision, latency, status and safe query hash recorded; no PII/secret logging. / 可审计但不暴露秘密。 |
| FR-14 | Optional inventory analysis / 库存分析 | P1 | Low-stock based on clearly timestamped inventory snapshot and threshold; reject if stale or unavailable. / 库存数据过期则提示。 |
| FR-15 | Optional query history / 查询历史 | P1 | Same user can view authorized historical query metadata; scope rechecked at retrieval time. / 重新授权检查。 |

## 7. Required output contract / 回答结构

A successful answer must include these **displayed fields**: `question`, `resolved_intent`, `metric_name`, `metric_version`, `value(s)`, `unit/currency`, `time_range`, `timezone`, `scope`, `chart_spec`, `result_table`, `query_evidence`, `source_data_as_of`, `limitations`, `request_id`. / 成功回答必须包含问题解析、指标、数字、期间、数据范围、图表、查询依据与限制。

No raw SQL from Dify/LLM is executed. If displaying SQL to an analyst, it is the **executed and sanitized backend-compiled statement**, not an LLM proposal. / 透明度面板展示经过后端编译实际执行的 SQL。

The above are planning wireframes, **not implemented UI**. / 属于规划，不是已实现页面。

## 9. Non-functional requirements / 非功能需求

| ID | Attribute / 属性 | Initial target / 初始目标 |
|---|---|---|
| NFR-01 | Security / 安全 | Zero unauthorized disclosure in defined test suite, read-only enforced at DB, threat model reviewed. |
| NFR-02 | Correctness / 正确性 | ≥90% end-to-end correctness on ≥60 supported golden questions; all core KPI reference tests pass. |
| NFR-03 | Auditability / 可审计 | 100% successful responses have evidence fields; errors have request ID and safe failure code. |
| NFR-04 | Latency / 延迟 | Initial p95 ≤15s for at least 30 representative local requests with declared hardware/provider conditions; review after measurement. |
| NFR-05 | Usability / 易用性 | ≥80% of defined tasks completed by ≥5 test users; review observations not only success rate. |
| NFR-06 | Availability / 可用性 | Local demo recoverable via documented setup; no production SLA promised. |
| NFR-07 | Maintainability / 可维护性 | Versioned metrics; tested compiler and rules; documented service contracts; automated regression gate. |
| NFR-08 | Cost / 成本 | Target near-zero local subscription costs; measure and cap LLM usage per session, provider-dependent. |
| NFR-09 | Privacy / 隐私 | Synthetic data only for MVP; no real customer PII; avoid sending query results to external LLM where unnecessary. |
| NFR-10 | Accessibility / 无障碍 | Keyboard-accessible main journey, labeled controls and chart data-table alternative; check during UI review. |

These thresholds are proposed **release gates**, not measured performance. / 均为目标，非已取得的测试成绩。

## 10. Dependencies / 依赖关系

- Approved business metric contracts **before** schema design. / 指标定义先于物理数据库。
- Approved data scopes and role model **before** LLM endpoint integration. / 权限定义先于 AI 接入。
- Golden-answer reference calculations **before** declaring the AI effective. / 建立标准答案后才测准确率。
- Dify-vs-direct orchestration comparison **before** final infrastructure commitment. / 比较之后决定 Dify 是否保留。

## 11. Acceptance gate / 产品范围审核

**No implementation until:** validated or explicitly accepted user assumptions; P0 scope frozen; metrics and calendar conventions approved; conceptual ERD and authorization boundary approved; threat model reviewed; test set design approved; owner signs off. / 未完成以上审核，不进入开发。
